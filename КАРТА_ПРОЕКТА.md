# КАРТА ПРОЕКТА CL-8 — маршрут ревью по шагам

Единственный рабочий документ проекта. Всё остальное (спека, старые отчёты, легаси) лежит в
`удаление/` и ждёт вашего решения. Этот файл ведёт вас через проект в том порядке, в котором
его стоит ревьюить: от идеи к таблицам, от таблиц к кодеру, от кодера к тестам и публикации.

---

## 0. Что это и зачем

**CL-8** — компактная 8-битная кодировка текста для кириллицы и латиницы:

- каждая буква базовой таблицы = ровно **1 байт** (коды 0–219);
- кириллица сжимается на ~45% относительно UTF-8 (там она стоит 2 байта/буква);
- диакритика 41 языка = **2 байта** (модификатор + база);
- всё остальное (эмодзи, CJK, арабский) прозрачно проходит через UTF-8-фоллбэк;
- ядро: `no_std`, ноль аллокаций, ноль зависимостей, ноль `unsafe`.

Ориентир качества — ваш крейт `shortest-color`: минимальный вес пакета, максимальная скорость.
Итог: пакет для crates.io — **20 файлов, ~35 KiB сжатый архив**, только то, что нужно для сборки.

### 2.1 Кодирование — приоритеты решения для каждого символа

`Encoder::encode` идёт по символам строки. **До** кодирования символа проверяется CAPS-ран
(шаг 0), затем `encode_char` выбирает первую подходящую ветку:

| Шаг | Условие | Результат |
|---|---|---|
| 0 | Впереди ран, несущий ≥3 заглавных, требующих case-shift | `CAPS_ON` (252) … ран … `CAPS_OFF` (253) |
| 1 | Пробел / перевод строки / таб | 1 служебный байт (232/233/234) |
| 2 | Символ есть в базовой таблице (включая прямые A-Z, А-Я, Ё) | 1 байт (0–219) |
| 3 | Составной символ из таблицы модификаторов (é, č, ї…) | 2 байта: модификатор (238–251) + база |
| 4 | Турецкая İ (U+0130) | 3 байта: DotAbove(251) + CASE_SHIFT(237) + 'i'(18) |
| 5 | Заглавная, чья строчная форма кодируема | CASE_SHIFT + (модификатор+) база; внутри CAPS-рана — без CASE_SHIFT |
| 6 | Всё остальное | UNI_ON (236) + сырые UTF-8 байты + терминатор 0xC0 |

Ключевая экономика шага 0 (спека 9.1). Платят за toggle только буквы, которым иначе нужен
префикс CASE_SHIFT: заглавная дополнительная кириллица (Є, Ї, Ђ, Ў…) и заглавная диакритика
(Č, Š, Ä…). Каждая такая буква экономит 1 байт, вся пара toggle-байт стоит 2 — поэтому порог
ровно 3 (на двух — ничья, и выбирается префикс, он не оставляет открытого состояния).

Ран **не обязан быть сплошным**. Символы, которые CAPS-режим не меняет — цифры, пунктуация,
пробелы и прямые заглавные (A-Z, А-Я, Ё) — стоят 1 байт что внутри режима, что снаружи,
поэтому они продлевают ран бесплатно и позволяют далеко разнесённым заглавным разделить одну
пару toggle-байт. Строчные буквы режим бы капитализировал, поэтому они ран всегда обрывают
(как и ß: у него есть заглавная форма ẞ). Ран закрывается сразу после последней заглавной —
хвостовые нейтральные символы его не удерживают.

### 2.2 Декодирование — диспетчер байтов

`Decoder::decode` — конечный автомат, один проход, для каждого байта первая подходящая ветка:

| Приоритет | Байт | Действие |
|---|---|---|
| 1 | (режим UNI_ON активен) | терминатор {0xC0,0xC1,0xF5..0xFF} закрывает режим (с валидацией UTF-8), иначе байт пишется как есть |
| 2 | 232/233/234 | пробел / \n / \t |
| 2 | 235 BACKSPACE | стереть последний записанный символ (целый кодпойнт) |
| 2 | 236 UNI_ON | открыть режим фоллбэка |
| 3 | 252/253 | CAPS_ON / CAPS_OFF (тумблер) |
| 3 | 254 EOM | завершить декодирование |
| 3 | 255 CANCEL | сбросить весь накопленный вывод |
| 4 | 237 CASE_SHIFT | в стек модификаторов |
| 5 | 238–251 | диакритика в стек (вторая подряд = ошибка StackedDiacritics) |
| 6 | 0–219 | базовый символ: разрешить стек (диакритика -> капитализация), применить CAPS-режим, записать UTF-8 |
| — | 220–231 | ошибка UnknownByte (зарезервировано) |

По окончании входа: незакрытый UNI_ON — ошибка `UnterminatedUnicodeMode`; непустой стек —
ошибка `DanglingModifier`.

### 2.3 Карта байтового пространства

| Диапазон | Значение |
|---|---|
| 0–9 | цифры |
| 10–35 | латиница a–z |
| 36–68 | кириллица а–я + ё (42) |
| 69–96 | дополнительная кириллица (є, ї, ђ, ґ, ј, љ, њ…) и нераскладываемые буквы (ß, æ…) |
| 97–160 | пунктуация, валюты, спецсимволы |

## 3. Маршрут ревью и все функции — файл за файлом

Рекомендованный порядок чтения. Для каждого файла перечислены **все** функции с логикой.

### Шаг 1. `tables/*.csv` — источники истины

- `base_table.csv`: строки `код,0xКОДПОЙНТ`, 220 записей, код строго последовательный от 0.
- `modifier_table.csv`: `код_базы,код_модификатора,0xРЕЗУЛЬТАТ`, 60 пар (например акут+e=é).
- `capitalize_table.csv`: `0xстрочная,0xзаглавная`, 89 нерегулярных пар (ђ→Ђ, é→É…).
  Регулярные пары (a↔A через ±0x20) в таблице НЕ хранятся — они считаются арифметикой.

### Шаг 2. `build.rs` — генератор (выполняется при компиляции)

| Функция | Что делает |
|---|---|
| `main()` | читает 3 CSV, вызывает парсеры, пишет `$OUT_DIR/tables.rs`, ставит `rerun-if-changed` |
| `clean(line)` | срезает комментарий `#` и пробелы; пустые строки -> None |
| `hex(field, ctx)` / `dec(field, ctx)` | парс числа c паникой с контекстом (ошибки таблиц должны валить сборку) |
| `lines_of(path)` | читает файл в нумерованные строки |
| `parse_base(path)` | валидирует: коды последовательны от 0 без дыр/дублей, кодпойнты уникальны и валидные скаляры |
| `parse_modifiers(path, base)` | валидирует: база существует, результаты не пересекаются с базовой таблицей и уникальны между собой |
| `parse_capitalize(path, base, modifiers)` | валидирует: строчная достижима (в базе или через модификатор), пары не рефлексивны, нет дублей |
| `emit(...)` | генерирует Rust-код: `BASE_TABLE: [u32; 220]`, `MODIFIER_TABLE: [(Modifier,u8,u32); 60]`, `CAPITALIZE_TABLE` (сортирована по строчной), `REVERSE_CAPITALIZE_TABLE` (сортирована по заглавной), `enum Modifier` с doc-комментариями |
| `MODIFIER_NAMES` (const) | 14 имён модификаторов, порядок жёстко соответствует кодам 238..251 |

Смысл: любая ошибка данных ловится **на компиляции**, рантайм таблицам верит безусловно.

### Шаг 3. `src/lib.rs` — публичная поверхность

- Атрибуты: `no_std` (без std-фичи), `forbid(unsafe_code)`, `warn(missing_docs, clippy::pedantic)`.
- Реэкспорты: `encode_into`, `decode_into`, `max_encoded_len`, `max_decoded_len`,
  `EncodeError`, `DecodeError`, `Modifier`, `ModifierStack`, три таблицы;
  под `alloc` — `encode`, `decode`.
- `SPEC_VERSION: &str` — пин версии спеки, проверяется тестом.

### Шаг 4. `src/consts.rs` — служебные байты

Константы SPACE=232, ENTER=233, TAB=234, BACKSPACE=235, UNI_ON=236, CASE_SHIFT=237,
MODIFIER_FIRST/LAST=238/251, CAPS_ON=252, CAPS_OFF=253, EOM=254, CANCEL=255,
CAPS_TOGGLE_THRESHOLD=3.

| Функция | Логика |
|---|---|
| `is_unicode_terminator(b)` | `b ∈ {0xC0, 0xC1, 0xF5..=0xFF}` — эти байты не могут начинать валидный UTF-8, поэтому однозначно закрывают режим фоллбэка |

### Шаг 5. `src/tables.rs` — доступ к таблицам

| Функция | Логика |
|---|---|
| `codepoint_of(code)` | код -> кодпойнт: прямой индекс в BASE_TABLE, O(1) |
| `code_of(codepoint)` | кодпойнт -> код. **Горячий путь O(1) арифметикой**: цифры, a–z, а–я (с дыркой под ё=42), A–Z, А–Я, ё/Ё. Остальное (пунктуация, доп. кириллица) — линейный скан кодов 69..160 |
| `apply_modifier(modifier, base)` | линейный поиск пары в MODIFIER_TABLE (60 записей) -> составной кодпойнт или None |
| `to_upper(cp)` | строчная -> заглавная: сначала арифметика −0x20 для a–z/а–я и ё→Ё, затем бинарный поиск в CAPITALIZE_TABLE |
| `from_upper_to_lower(cp)` | заглавная -> строчная: арифметика +0x20, Ё→ё, İ→i, затем бинарный поиск в REVERSE_CAPITALIZE_TABLE |
| `find_modifier_pair_for_codepoint(cp)` | обратный поиск: составной кодпойнт -> (модификатор, база) |

### Шаг 6. `src/encode.rs` — энкодер

| Функция | Логика |
|---|---|
| `encode_into(input, output)` | публичная точка входа: создаёт `Encoder` и кодирует всю строку |
| `Encoder::new()` | нулевое состояние: offset=0, CAPS выключен, фоллбэк закрыт |
| `Encoder::encode(input, output)` | 1) `validate_nfc`; 2) цикл по символам: детект CAPS-рана (см. ниже), `encode_char`, закрытие рана после последней буквы; 3) закрытие фоллбэка терминатором 0xC0 в конце. Возвращает число записанных байт |
| `Encoder::validate_nfc(input)` | отклоняет standalone combining marks (U+0300..U+036F) -> `NotNfcNormalized`. Ядро не умеет нормализовывать само (это потребовало бы огромных таблиц Unicode) — вход обязан быть в NFC |
| `Encoder::ensure_unicode_closed(output)` | если фоллбэк открыт — записать 0xC0 и закрыть (вызывается перед любым не-фоллбэк байтом) |
| `Encoder::encode_char(ch, output)` | 6-шаговый конвейер приоритетов из раздела 2.1 |
| `Encoder::encode_base_char(code, output)` | тонкая обёртка над `write_byte` |
| `Encoder::needs_case_shift(ch)` | «стоит ли буква лишний байт CASE_SHIFT вне CAPS-рана». Быстрые отсечения без сканов таблиц: ASCII, базовая кириллица (0x410–0x44F, ё, Ё), İ -> false. Далее: не в базе напрямую, но её строчная форма кодируема -> true |
| `Encoder::is_caps_neutral(ch)` | «пройдёт ли символ через активный CAPS-режим без изменений». Пробел/\n/\t -> да (они служебные байты и режима не касаются); иначе символ обязан быть в базовой таблице И иметь `to_upper == None` |
| `Encoder::scan_caps_run(rest)` | меряет ран, уже начавшийся на case-shift-букве: идёт вперёд, считает заглавные (`shifts`) и длину до последней из них (`run_len`); нейтральные символы копятся в `pending` и засчитываются в длину только если дальше встретилась ещё одна заглавная; первый не-нейтральный не-заглавный символ обрывает скан |
| `Encoder::find_modifier_pair(cp)` | линейный поиск составного кодпойнта в MODIFIER_TABLE |
| `Encoder::encode_unicode_fallback(ch, output)` | открыть UNI_ON (если ещё нет), записать сырые UTF-8 байты символа |
| `Encoder::write_byte(byte, output)` | запись с проверкой границ -> `OutputTooSmall` |
| `max_encoded_len(n)` | верхняя граница: `n*3+2` (худший случай — İ по 3 байта + пара служебных) |

Детект CAPS-рана в `encode`: когда CAPS не активен и `needs_case_shift(ch)` — посчитать
длину непрерывного рана вперёд (`take_while`); если ≥3 — записать CAPS_ON, включить режим,
запомнить остаток. После каждой буквы рана остаток уменьшается; на нуле пишется CAPS_OFF.

### Шаг 7. `src/decode.rs` — декодер

| Функция | Логика |
|---|---|
| `decode_into(input, output)` | публичная точка входа: создаёт `Decoder` |
| `Decoder::new()` | нулевое состояние (позиция, offset, стек, CAPS, фоллбэк, флаг EOM) |
| `Decoder::decode(input, output)` | цикл `process_byte` до конца входа или EOM; финальные проверки: фоллбэк закрыт, стек пуст |
| `Decoder::process_byte(byte, output)` | диспетчер из раздела 2.2 |
| `Decoder::handle_unicode_mode(byte, output)` | внутри фоллбэка: терминатор -> `validate_canonical` + `from_utf8` на накопленном сегменте, закрыть режим; иначе записать байт как есть |
| `Decoder::handle_backspace(output)` | пустой вывод -> `NothingToErase`; иначе откатить offset на длину последнего UTF-8 кодпойнта |
| `Decoder::write_char(ch, output)` | записать символ как UTF-8 (до 4 байт) с проверкой границ |
| `Decoder::write_byte(byte, output)` | сырой байт с проверкой границ (используется фоллбэком) |
| `utf8_char_len(output, offset)` | идёт назад от offset до стартового байта UTF-8 -> длина последнего символа (для BACKSPACE) |
| `max_decoded_len(n)` | верхняя граница: `n*4` (один байт входа никогда не даёт больше 4 байт UTF-8) |

Обработка базового байта (< 232): проверить валидность кода, `modifier_stack.resolve`
(диакритика, потом капитализация), затем если CAPS активен — `to_upper`, записать, очистить стек.

### Шаг 8. `src/modifier.rs` — стек модификаторов декодера

Максимум 2 элемента: один case-shift + одна диакритика (спека 8.4). `Copy`-тип, живёт в регистрах.

| Функция | Логика |
|---|---|
| `ModifierStack::new()` / `is_empty()` / `origin()` | конструктор, проверка пустоты, позиция первого модификатора (для ошибок) |
| `push_case_shift(pos)` | флаг капитализации; повторный case-shift идемпотентен (не ошибка — спека 9.1) |
| `push_diacritic(modifier, pos)` | вторая диакритика подряд -> `StackedDiacritics` |
| `resolve(base, pos)` | спецслучай İ (DotAbove+case-shift+'i' -> U+0130); иначе: 1) `apply_modifier` (нет пары -> `UndefinedCombination`), 2) `to_upper` если был case-shift |
| `clear()` | сброс после каждого базового символа |

| `is_modifier_result(cp)` (приватная) | есть ли кодпойнт среди результатов модификаторов |

### Шаг 11. `src/error.rs` — ошибки

`DecodeError`: UnknownByte, StackedDiacritics, DanglingModifier, UndefinedCombination,
UnterminatedUnicodeMode, InvalidUtf8InUnicodeMode, NothingToErase, OutputTooSmall.
`EncodeError`: OutputTooSmall, NotNfcNormalized.

Оба — `Copy`, `#[non_exhaustive]`, контекст только числами (позиция/байт) — без аллокаций.
`Display` реализован **безусловно** (работает в no_std); `std::error::Error` — только под `std`.

### Шаг 12. `src/alloc_api.rs` — обёртки (feature = "alloc")

| Функция | Логика |
|---|---|
| `encode(input)` | выделить `vec![0; max_encoded_len]`, вызвать `encode_into`, `truncate` |
| `decode(input)` | выделить буфер по `max_decoded_len`, `decode_into`, `String::from_utf8` |

Единственное место в крейте, где есть аллокации — и оно отключено по умолчанию.

## 8. Известные особенности (осознанные, не баги)

- **Вход обязан быть в NFC.** Ядро не нормализует (это тянет огромные Unicode-таблицы и
  зависимости) — standalone combining marks отклоняются ошибкой. Задокументировано в README.
- **CANCEL (255) сбрасывает только вывод**, не состояние стека — CANCEL с последующим
  висячим модификатором даст `DanglingModifier`. Внутри фоллбэка байт 255 трактуется как
  терминатор режима. Соответствует букве спеки; если захотите иной семантики — точка входа
  `Decoder::process_byte`, ветка CANCEL.
- **`european_diacritics` даёт всего 1.7%** — честно: диакритика = 2 байта против 2 байт
  UTF-8, выигрыш только на CAPS-ранах и заглавных. Выигрыша тут и не обещалось.
- **`rust-version = "1.74"`** — заявлен, но на машине не проверялся (нет тулчейна 1.74);
  синтаксис в коде консервативный.
